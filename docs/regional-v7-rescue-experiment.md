# V7 D5 离线救援可行性实验（未发布）

日期：2026-10-15。所有评估在本地内存中进行，没有更改已发布的 `regionalV7Bank.json`、原生成器、历史谜题身份或 UI。运行：`node tools/runRegionalV7Difficulty.mjs` 与 `node tools/runRegionalV7Rescue.mjs`。两个运行器分别设有 90 秒子进程硬限。结果不是玩家通过率。

## 为什么需要独立评估

原 V7 题库按稳定 ID 拓扑取牌顺序写入连续完整鸟名；原 fixed-ID baseline 也按最小 ID 取牌，因此其 25/25 胜与构造路径同构，不能证明人的可玩性。题库具备引擎回放的存在性证书，独立搜索状态仍为 `NOT_RUN`。

独立诊断只使用当前可见牌、槽内字、剩余拼词配额和合法动作，不读取 `winningSolution`、证书 `takeOrder` 或未露牌的字。每局每策略 5 个固定种子，最多 180 个动作。两种词导向策略区别：`word-seeking` 选择缺字最少的一个目标词；`word-cluster` 按可见字对所有未完成词的缺字贡献计分。随机打平不按 tile ID。

|---|---:|---:|---:|---:|---:|
| D1 | 22/25 | 21/25 | 25/25 | 25/25 | 15/25 |
| D2 | 0/25 | 1/25 | 25/25 | 25/25 | 0/25 |

| D4 | 0/25 | 0/25 | 13/25 | 4/25 | 0/25 |

全部失败均为十槽满；无动作预算耗尽导致的 `UNKNOWN`。D2 两种独立词导向均显著优于随机，因此可以探索目标词教学；D3–D4 的策略结果分化；D5 不能据现有证书宣称体验合格。每局最大/最终槽占用、剩余牌、已拼词数、死局类型和固定试验种子可由脚本重现。

## 预注册 D5 救援试验

产品侧预先规定：原板连续撤销每试次最多 20 次单步撤销和 180 次前进操作，5 种子/局；内存重排每局最多 8 个候选，仅在 5 个训练种子上选候选，再用另 5 个留出种子评估，不得再按留出结果挑选。候选必须保持 90 字词语配额并有引擎回放证书。进入真人原型的门槛是留出集总胜局至少 13/25，且五局各至少 1/5；该门槛仍不是商业质量认证。

原板撤销：五局各 0/5，总计 **0/25**；所有试次都用了 20 次撤销仍失败。撤销策略只在死局时回到此前实际可见状态，尝试该状态尚未采取的可见合法动作；不访问隐藏字或构造证书。这个窄实验不证明撤销机制无价值，只说明 20 次单步撤销配合这一策略不足以救活现有 D5。

内存重排：对每局原有词语出现次数做确定性乱序，按原证书取牌顺序把新字序分配到相同 90 个位置。构造时可使用原证书取牌顺序；每个候选均经引擎回放认证，词语和字的多重集合不变，并使用 `regional-v7-rescue:` 实验身份。选择/评估策略只接收无证书谜题，不能看到隐藏字。共构造 40 候选，训练 200 次，留出 25 次；实测运算约 1 秒（依设备而异）。

|---|---:|---:|---:|
| 1 | 1/5 | 1/5 | 4/5 |
| 2 | 0/5 | 0/5 | 5/5 |
| 3 | 0/5 | 0/5 | 5/5 |
| 4 | 0/5 | 0/5 | 5/5 |
| 5 | 1/5 | 3/5 | 2/5 |

留出总计 **4/25**，且三局完全没有成功，因此不达门槛。词序重排候选可能互有相同板面哈希；脚本报告各局实际唯一哈希数，避免把候选数量误当独立设计数量。候选都没有进入正式题库，原有谜题 ID 与进度保持不变。

下一步应进行版本化的 D5 内容与版面重设计，随后重新做独立非见证试验和真人试玩。D2 可先试目标词引导与多步撤销。不得把本实验策略结果解释为真人难度或把训练胜率当作留出泛化率。
