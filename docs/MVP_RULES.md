# 《字里有鸟》PR2 规则

## 产品假设

被遮挡的字、有限的底部字槽，以及短鸟与长鸟之间的取舍，可以为鸟名拼字带来持续压力。

## 核心循环

从互相交叠的棋盘取走当前未被遮挡的字，放入 10 格字槽；系统自动识别字槽中所有可拼鸟名，玩家点击其中一只鸟即可清除所需字块、获得分数。棋盘与字槽都清空才完成关卡。

## 棋盘与字槽

- 竖屏优先，主要测试尺寸为 390 × 844。
- 棋盘使用显式手工坐标、确定性的逻辑层级和跨鸟名阻挡关系，不使用物理引擎。
- 只有所有阻挡者都已移除的字块可以拿取；字块进入第一个空字槽且不能重复拿取。
- 字槽固定 10 格。满槽且仍有鸟可拼时提示先拼鸟；满槽且无鸟可拼时游戏结束。
- 一个上层字可以同时挡住多个下层字，一个下层字也可能需要移走多个阻挡者才能露出。

## 拼鸟与计分

- 鸟名识别与字进入字槽的顺序无关，同时可拼成多只鸟时全部显示，系统不会自动选择或消耗。
- 点击鸟名后立即消耗所需字块；重复字符按字槽顺序优先使用，同一字块不能重复使用，无关字块保持不变。
- 非法或当前无法拼成的鸟名不改变字槽或得分。2 字鸟 10 分、3 字鸟 30 分、4 字鸟 70 分。
- 鸟使用稳定语义 ID 与素材键，例如 `bird:xique` / `xique`。

## 关卡数据与第三关生成

第一关（22 块、2 层）和第二关（33 块、3 层）仍使用原有手工数据。第三关使用 59 个稳定位置：40 个五层主棋盘位置、12 个外围辅助位置、7 个固定阻挡顺序的盲堆位置。位置只保存 ID、坐标、逻辑层、阻挡关系和可选区域，完全不携带鸟种含义；因此换种子只改变字符，不改变 `l3-m01` 等位置 ID 或几何关系。

第三关生成严格分为三步：

1. 从现有 16 种鸟的完整目录中选择鸟名组合；字符总数必须恰好等于 59，不允许填充字。
2. 默认要求至少 12 种鸟、每种最多出现 2 次；白鹭／大白鹭／小白鹭家族至少选中 2 种，喜鹊／灰喜鹊家族两种都选中。约束无法满足时返回明确失败。
3. 使用 32 位 `mulberry32` 伪随机数生成器和 Fisher–Yates 洗牌，把完整字符多重集独立分配到位置。内容采样使用 `seed ^ 0xa5a5a5a5` 的独立随机流，字符放置使用原始 seed；确定性路径不调用 `Math.random()`。

相同 seed、目录和约束必定得到相同棋盘，不同 seed 会改变鸟名组合和字符位置。复现某一候选可调用 `generateLevel3Content(seed)`。运行时只加载已经离线验证的 seed，不执行搜索。

## 可解性验收

离线验证器通过真实核心函数执行取字和一键拼鸟，检查遮挡、10 格字槽、竞争鸟名、清盘后的字槽处理以及“棋盘和字槽都为空”胜利条件。深度优先搜索同时枚举“拼鸟”和“继续取字”，所以允许有意延后已经可用的组合；状态按已移除位置和字槽字符多重集记忆，并按开路、可拼组合和容量排序。它返回：

- `SOLVED`：附带可逐步重放的动作路径；只有再次通过核心引擎重放到 `level_complete` 才能接受。
- `UNSOLVABLE`：仅在搜索空间确实穷尽时返回。
- `SEARCH_LIMIT_REACHED`：节点或时间预算耗尽，绝不当作不可解证明。

验证器默认预算为 250,000 节点和 5,000 ms。100-seed 实验使用更严格的每候选 5,000 节点／250 ms，并将候选尝试总数固定为 100，避免无界重生成。

原型当前固定使用已验证 seed `4`（13 种鸟、单种最多 2 次）。其成功重放路径如下；每段先按顺序取括号内位置，再点击箭头后的鸟，上一段未消费的字会继续留在字槽：

1. `m03,m07,m01 → 山斑鸠`; `m02,m16,m15,m06,m23 → 白头鹎`; `m14,m21,m22 → 苍鹭`; `m30 → 戴胜`。
2. `m24,m28,m29,q01,q02,q03 → 夜鹭`; `q04,q05,q06,m04 → 夜鹭`; `m12 → 红隼`; `m11,m20 → 珠颈斑鸠`。
3. `m13,m18 → 红腹锦鸡`; `m32,m19 → 池鹭`; `m27,x02 → 喜鹊`; `m05,m08 → 白头鹎`。
4. `m09,m10,m17,m31 → 小白鹭`; `m25,m26,x10 → 灰喜鹊`; `m37 → 池鹭`; `m33,x05 → 山斑鸠`。
5. `m34,m35,m39 → 白鹭`; `m36,x06 → 珠颈斑鸠`; `m38,m40,q07,x09 → 苍鹭`; `x01,x11,x04 → 灰喜鹊`; `x03,x07 → 红隼`; `x08,x12 → 红腹锦鸡`。

这里的短 ID 都省略共同的 `l3-` 前缀；源码中的完整、机器可重放动作保存在 `src/core/level3Fixture.ts`。

## 难度诊断

`pnpm run evaluate:level3` 使用固定 seed 1–100 生成候选，并记录种类数、最大重复数、求解状态、节点和耗时；随后用随机合法动作、立即拼鸟、最短鸟、最高分、优先开路、容量感知和有限前瞻七种策略试玩已接受候选。随机、开路、容量感知和前瞻策略都可以选择暂不拼鸟。

这些胜率和求解耗时只用于发现容量压力、贪心偏差和异常候选，不能代表人类难度或证明“好玩”。盲堆仍只有当前顶部字符可见；给求解器完整关卡数据只是离线验收手段。

## 完成与失败

- 棋盘和字槽同时为空时，显示关卡完成、得分、完成鸟数和重新挑战按钮。
- 棋盘已空但字槽仍有可拼鸟时继续游戏，并提示“棋盘已清空，拼完字槽里的鸟。”
- 棋盘已空、字槽非空且无鸟可拼时失败。
- 棋盘未空、字槽已满且无鸟可拼时失败；若仍有鸟可拼则继续游戏，但不能再从棋盘取字。

## PR2 明确不做

三选一候选循环、任意运行时程序化布局几何、进度系统、账号、后端、持久化、广告、任务、商店、排行榜、剧情、鸟类百科、正式美术、连击、保底、动态难度、Cocos 或微信接入。

## 人工试玩要回答

1. 两个可拿字之间是否让人犹豫？
2. 字槽占用是否产生张力？
3. 是否会为了长鸟名保留某个字？
4. 移开一块、露出下一块是否带来期待？
5. 失败原因是否清楚？
6. 是否想立即重试同一关？
