# 《字里有鸟》PR2 规则

## 产品假设

被遮挡的字、有限的底部字槽，以及短鸟与长鸟之间的取舍，可以为鸟名拼字带来持续压力。

## 核心循环

从互相交叠的棋盘取走当前未被遮挡的字，放入 10 格字槽；系统自动识别字槽中所有可拼鸟名，玩家点击其中一只鸟即可清除所需字块、获得分数。棋盘与字槽都清空才完成关卡。

## 棋盘与字槽

- 竖屏优先，主要测试尺寸为 390 × 844。
- 棋盘使用显式手工坐标、确定性的逻辑层级和跨鸟名阻挡关系，不使用物理引擎。
- 只有所有阻挡者都已移除的字块可以拿取；字块进入第一个空字槽且不能重复拿取。
- 字槽固定 10 格。满槽且仍有鸟可拼时提示先拼鸟；满槽且无鸟可拼时游戏结束。
- 一个上层字可以同时挡住多个下层字，一个下层字也可能需要移走多个阻挡者才能露出。

## 拼鸟与计分

- 鸟名识别与字进入字槽的顺序无关，同时可拼成多只鸟时全部显示，系统不会自动选择或消耗。
- 点击鸟名后立即消耗所需字块；重复字符按字槽顺序优先使用，同一字块不能重复使用，无关字块保持不变。
- 非法或当前无法拼成的鸟名不改变字槽或得分。2 字鸟 10 分、3 字鸟 30 分、4 字鸟 70 分。
- 鸟使用稳定语义 ID 与素材键，例如 `bird:xique` / `xique`。

## 三个手工关卡

- 第一关：22 块、2 层，低压力教学。
- 第二关：33 块、3 层，增加分支取舍。
- 第三关：59 块；40 块五层主棋盘、12 块外围补给字、7 块固定顺序盲堆，强化字槽压力。

每个字块都显式定义 ID、字符、坐标、层级与阻挡者。鸟名中的字被拆散到不同区域和深度，棋盘不存在“一摞就是一只鸟”的结构。

每关都在关卡数据中保存一条由“取指定字块 → 一键拼成指定鸟名”组成的人工通关路径，测试会逐动作重放并检查露出状态、10 格上限及最终清空。路径摘要：

- 第一关：喜鹊 → 白鹭 → 红隼 → 戴胜 → 苍鹭 → 喜鹊 → 白鹭 → 苍鹭 → 夜鹭 → 池鹭 → 红隼。
- 第二关：灰喜鹊 → 大白鹭 → 小白鹭 → 白头鹎 → 黑水鸡 → 山斑鸠 → 树麻雀 → 灰喜鹊 → 大白鹭 → 黑水鸡 → 山斑鸠。
- 第三关：红腹锦鸡 → 珠颈斑鸠 → 红隼 → 大白鹭 → 灰喜鹊 → 红腹锦鸡 → 珠颈斑鸠 → 大白鹭 → 红腹锦鸡 → 珠颈斑鸠 → 灰喜鹊 → 小白鹭 → 黑水鸡 → 红腹锦鸡 → 珠颈斑鸠 → 喜鹊 → 白鹭 → 山斑鸠。

这些路径证明所录入关卡存在一条可执行通路，但不宣称对任意拿字顺序进行数学可解性证明。

## 第三关决策点

### 1. 短鸟还是长鸟

- 当前可见／可取：开局可取的 `腹、锦、颈` 等储备字；移开 `l3-m01`、`l3-m02`、`l3-m03` 后，`红、鸡、隼、珠、斑` 分别露出。
- 相关被压字：下一层的另一组 `红、鸡` 仍由跨鸟名阻挡链压住。
- 字槽：典型状态为 `腹、锦、颈、红`，占 4 格；继续取 `隼` 或 `鸡` 会到 5 格。
- 合理选择：取 `隼` 先拼 10 分的红隼，或取 `鸡` 用已有 `腹、锦` 拼 70 分的红腹锦鸡。
- 短期收益：红隼立即少占两格；长鸟一次释放四格并取得高分。
- 未来风险：先拼红隼会留下 `腹、锦` 等待更深的下一枚红与鸡；等长鸟则要多承受一格容量压力。
- 不明显原因：两种选择都合法且不会立即判死，但改变后续挖掘时的闲置字数量。

### 2. 是否提前拿补给字

- 当前可见／可取：外围补给区始终可见 `腹、锦、颈、大、小、灰、斑`。
- 相关被压字：对应的 `红、鸡、珠、喜、鹊、白、鹭` 分散在主棋盘第二至第五层。
- 字槽：开局为 0 格；每提前保留一个补给字就永久占一格，直到相应深层目标露出。
- 合理选择：先拿 `腹、锦` 为下一只红腹锦鸡做准备，或保留在棋盘上，把空槽留给挖掘字。
- 短期收益：提前拿取保证资源在手；延后拿取保持最大机动空间。
- 未来风险：过早囤积会让盲堆和主棋盘挖掘字挤满槽；过晚则可能在路线判断中忘记该资源仍未取。
- 不明显原因：补给字没有被挡且不会消失，价值来自拿取时机而非可获得性。

### 3. 容量受限时继续深挖

- 当前可见／可取：中段可见 `鸡`（`l3-m18`），其下是 `黑`，再下是 `水`；盲堆同时逐步露出 `珠、斑、鸠、白`。
- 相关被压字：`黑` 必须先移走 `鸡`，`水` 又必须先移走 `黑`。
- 字槽：若玩家已经保留两至四个补给字和一个盲堆字，连续拿 `鸡、黑、水` 会把占用推向 7–9 格。
- 合理选择：继续三步深挖并拼黑水鸡，或先利用已经成形的短鸟／长鸟清槽，再回来挖。
- 短期收益：深挖一次打开 `水、山` 两条后续路线；先清槽则降低立即失败风险。
- 未来风险：盲目深挖可能在最后一格仍无鸟可拼；过早消费共享字可能拆掉计划中的长鸟。
- 不明显原因：最大开路收益与最大瞬时槽压来自同一条阻挡链。

盲堆字符顺序固定，只有当前顶字可见；它用于有限信息下的风险管理，不是随机猜字。离线评估工具位于 `tools/level3-evaluation.test.ts`，只参与开发验证，不进入 Vite 生产包。

## 完成与失败

- 棋盘和字槽同时为空时，显示关卡完成、得分、完成鸟数和重新挑战按钮。
- 棋盘已空但字槽仍有可拼鸟时继续游戏，并提示“棋盘已清空，拼完字槽里的鸟。”
- 棋盘已空、字槽非空且无鸟可拼时失败。
- 棋盘未空、字槽已满且无鸟可拼时失败；若仍有鸟可拼则继续游戏，但不能再从棋盘取字。

## PR2 明确不做

三选一候选循环、程序化关卡、进度系统、账号、后端、持久化、广告、任务、商店、排行榜、剧情、鸟类百科、正式美术、连击、保底、动态难度、Cocos 或微信接入。

## 人工试玩要回答

1. 两个可拿字之间是否让人犹豫？
2. 字槽占用是否产生张力？
3. 是否会为了长鸟名保留某个字？
4. 移开一块、露出下一块是否带来期待？
5. 失败原因是否清楚？
6. 是否想立即重试同一关？
