# 《字里有鸟》PR2 规则

## 产品假设

被遮挡的字、有限的底部字槽，以及短鸟与长鸟之间的取舍，可以为鸟名拼字带来持续压力。

## 核心循环

从互相交叠的棋盘取走当前未被遮挡的字，放入 10 格字槽；系统自动识别字槽中所有可拼鸟名，玩家点击其中一只鸟即可清除所需字块、获得分数。棋盘与字槽都清空才完成关卡。

## 棋盘与字槽

- 竖屏优先，主要测试尺寸为 390 × 844。
- 棋盘使用显式手工坐标、确定性的逻辑层级和跨鸟名阻挡关系，不使用物理引擎。
- 只有所有阻挡者都已移除的字块可以拿取；字块进入第一个空字槽且不能重复拿取。
- 字槽固定 10 格。满槽且仍有鸟可拼时提示先拼鸟；满槽且无鸟可拼时游戏结束。
- 一个上层字可以同时挡住多个下层字，一个下层字也可能需要移走多个阻挡者才能露出。

## 拼鸟与计分

- 鸟名识别与字进入字槽的顺序无关，同时可拼成多只鸟时全部显示，系统不会自动选择或消耗。
- 点击鸟名后立即消耗所需字块；重复字符按字槽顺序优先使用，同一字块不能重复使用，无关字块保持不变。
- 非法或当前无法拼成的鸟名不改变字槽或得分。2 字鸟 10 分、3 字鸟 30 分、4 字鸟 70 分。
- 鸟使用稳定语义 ID 与素材键，例如 `bird:xique` / `xique`。

## 三个手工关卡

- 第一关：22 块、2 层，低压力教学。
- 第二关：33 块、3 层，增加分支取舍。
- 第三关：44 块、4 层，强化字槽压力。

每个字块都显式定义 ID、字符、坐标、层级与阻挡者。鸟名中的字被拆散到不同区域和深度，棋盘不存在“一摞就是一只鸟”的结构。

每关都在关卡数据中保存一条由“取指定字块 → 一键拼成指定鸟名”组成的人工通关路径，测试会逐动作重放并检查露出状态、10 格上限及最终清空。路径摘要：

- 第一关：喜鹊 → 白鹭 → 红隼 → 戴胜 → 苍鹭 → 喜鹊 → 白鹭 → 苍鹭 → 夜鹭 → 池鹭 → 红隼。
- 第二关：灰喜鹊 → 大白鹭 → 小白鹭 → 白头鹎 → 黑水鸡 → 山斑鸠 → 树麻雀 → 灰喜鹊 → 大白鹭 → 黑水鸡 → 山斑鸠。
- 第三关：红腹锦鸡 → 红隼 → 珠颈斑鸠 → 喜鹊 → 白鹭 → 戴胜 → 灰喜鹊 → 白头鹎 → 黑水鸡 → 山斑鸠 → 红腹锦鸡 → 珠颈斑鸠 → 红腹锦鸡 → 珠颈斑鸠。

这些路径证明所录入关卡存在一条可执行通路，但不宣称对任意拿字顺序进行数学可解性证明。

## 完成与失败

- 棋盘和字槽同时为空时，显示关卡完成、得分、完成鸟数和重新挑战按钮。
- 棋盘已空但字槽仍有可拼鸟时继续游戏，并提示“棋盘已清空，拼完字槽里的鸟。”
- 棋盘已空、字槽非空且无鸟可拼时失败。
- 棋盘未空、字槽已满且无鸟可拼时失败；若仍有鸟可拼则继续游戏，但不能再从棋盘取字。

## PR2 明确不做

三选一候选循环、程序化关卡、进度系统、账号、后端、持久化、广告、任务、商店、排行榜、剧情、鸟类百科、正式美术、连击、保底、动态难度、Cocos 或微信接入。

## 人工试玩要回答

1. 两个可拿字之间是否让人犹豫？
2. 字槽占用是否产生张力？
3. 是否会为了长鸟名保留某个字？
4. 移开一块、露出下一块是否带来期待？
5. 失败原因是否清楚？
6. 是否想立即重试同一关？
